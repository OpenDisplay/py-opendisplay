# Reading a 3.0 Device (piece 2a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the library recognise a firmware 3.0 device and read what it says about itself (identity, advertisement state, refusals, config packets) without changing how anything is written or drawn.

**Architecture:** Four independent additions, each its own branch and pull request off `main`: a READ_IDENT command with a `DeviceIdent` model, new state fields on `AdvertisementData`, three typed refusal exceptions, and length-prefixed config packets (draft PR #198 updated). Pure parsing lives in `protocol/` and `models/`; the device class only gains `read_ident()`.

**Tech Stack:** Python 3.13, `uv`, pytest (asyncio_mode=auto), ruff, mypy strict, pylint, prek.

**Spec:** `docs/superpowers/specs/2026-11-15-v3-read-side-design.md`. Real frames from hardware: `scratch/captures-OD4064C9-fw3.0.2.md`.

## Global Constraints

- Source of truth for layouts and values: `Firmware_Unified` `upstream/main`, `shared/protocol/opendisplay_protocol.h` and `opendisplay_structs.h`. Fetch before reading; local branches go stale.
- Additive only. No existing public name, signature or exception changes. `tests/unit/test_public_api_snapshot.py` is regenerated in a task only for names that task adds (`UPDATE_API_SNAPSHOT=1`), and the diff of `tests/unit/data/public_api.json` must show additions only.
- A 2.x device behaves as before, with one exception the spec allows: an advertisement whose 11 dynamic bytes are all `0xFF` yields no button, touch or sensor data.
- Raw bytes stay the single source for packets the library only partly understands; nothing is re-encoded.
- New exceptions subclass `ProtocolError`.
- Tests must check behaviour, not restate code: no `isinstance`-only or `name == own name` assertions, no test that cannot fail.
- `uv` only. Commit with `uv run git commit` (the hook needs `prek` on PATH). Stage files by name. Conventional Commit messages; pull request titles are plain sentences without a type prefix. Never bump `version`.
- Each task: own branch from current `main`, `uv run pytest -q` and `uv run prek run --all-files` clean before its commit. Pushing and opening the pull request needs the user's go-ahead.
- Never print device keys. Fixtures taken from real devices have key and password fields zeroed.

## Review Focus

1. **Identity reply longer than this library knows.** A later firmware appends bytes after the tail; they must be kept in `DeviceIdent.extra` and everything before them still parsed. Test in Task 1.
2. **Identity reply cut short** (fewer bytes than `5 + count * 7`, or a tail of 1 to 5 bytes). Must raise `InvalidResponseError` naming the lengths, not `IndexError` or `struct.error`. Test in Task 1.
3. **Legacy 11-byte advertisement.** It has no status byte; the new state fields must be `None`, not `False`, and `unconfigured` must not fire on a legacy payload. Test in Task 2.
4. **A refusal code the library does not know** (for example `FF 70 0A 00`). Must keep today's behaviour exactly, including the compressed-to-uncompressed fallback. Test in Task 3.
5. **A length-prefixed packet whose declared length runs past the end of the config.** Must be kept in `unparsed_tail` with a warning and written back unchanged, never dropped. Test in Task 4 (already in #198; keep it).

# models/ident.py
class FirmwareTarget(IntEnum):
    ESP32 = 0x01
    NRF54 = 0x02
    EFR32BG22 = 0x03
    NRF52811 = 0x04
    NRF52840 = 0x05
    TELINK = 0x06            # provisional in the firmware

@dataclass(frozen=True)
class IdentDisplay:
    panel_ic_type: int
    pixel_width: int
    pixel_height: int
    color_scheme: int        # raw wire value, same as DisplayConfig.color_scheme

@dataclass(frozen=True)
class DeviceIdent:
    proto_minor: int
    fw_target: FirmwareTarget | int      # int when the value is not a known member
    displays: tuple[IdentDisplay, ...]
    flags: int | None = None             # raw tail flags byte; None when the reply has no tail (2.x)
    max_config: int | None = None
    max_seq_steps: int | None = None
    escapes: int | None = None
    extra: bytes = b""                   # bytes after the known tail, verbatim
    @property
    def has_tail(self) -> bool: ...          # flags is not None
    @property
    def config_driven(self) -> bool | None: ...     # flags & 0x01; None without a tail
    @property
    def needs_migration(self) -> bool | None: ...   # flags & 0x02
    @property
    def builtin_driver(self) -> bool | None: ...    # flags & 0x04
    @property
    def supports_window(self) -> bool | None: ...   # escapes & 0x01
    @property
    def supports_fill(self) -> bool | None: ...     # escapes & 0x02

# protocol/commands.py
CommandCode.READ_IDENT = 0x0046
def build_read_ident_command() -> bytes        # b"\x00\x46"

# protocol/responses.py
def parse_read_ident(data: bytes) -> DeviceIdent

# exceptions.py
class IdentNotSupportedError(ProtocolError)

# device/facade.py
TIMEOUT_IDENT = 2.0
@_serialized
async def read_ident(self) -> DeviceIdent
```

Wire layout: `[0x00][0x46][proto_minor][fw_target][display_count]`, then `display_count` records of `[panel_ic_type:2 LE][pixel_width:2 LE][pixel_height:2 LE][color_scheme:1]`, then on 3.0 the tail `[flags:1][max_config:2 LE][max_seq_steps:2 LE][escapes:1]`, then possibly more bytes.

`parse_read_ident` rules:
- reply shorter than 5 bytes, or echo not `0x0046` (high bit allowed, as `strip_command_echo` does) -> `InvalidResponseError`;
- fewer than `5 + count * 7` bytes -> `InvalidResponseError` with both lengths in the message;
- exactly at the end of the records -> no tail, tail fields `None`;
- 6 or more bytes after the records -> tail parsed, the rest into `extra`;
- 1 to 5 bytes after the records -> `InvalidResponseError` (a truncated tail).

`read_ident` rules: write and read on `self._conn` directly, as `read_firmware_version` does (the command is plaintext on every firmware). Read with `TIMEOUT_IDENT`. Raise `IdentNotSupportedError` when the device does not implement the command, which on hardware shows as one of: no answer (a timeout: chain it with `from`), the 3-byte `[00][46][FE]` frame, or a NACK starting `[FF][46]`. The message says that firmware before 3.0 (BG22 before 2.3) does not answer READ_IDENT.

# exceptions.py
class NeedsMigrationError(ProtocolError)     # the device has no usable drive data for its display
class PanelBusyError(ProtocolError)          # transient: the panel stayed BUSY; retry
class ConfigWriteBusyError(ProtocolError)    # transient: a display pass is running; retry

# protocol/responses.py
UPLOAD_START_NACK_NEEDS_MIGRATION = 0x08
UPLOAD_START_NACK_PANEL_BUSY = 0x09
CONFIG_WRITE_NACK_BUSY = 0x01
def raise_for_upload_start_refusal(opcode: int, err: int) -> None
    # opcode in {0x70, 0x76, 0x80}: 0x08 -> NeedsMigrationError; 0x09 on 0x70 / 0x76 -> PanelBusyError; else returns
def raise_for_config_write_refusal(response: bytes) -> None
    # [FF][41 or 42][01][00] -> ConfigWriteBusyError; anything else returns
```

Where they are called:

| Site | Today | After |
|---|---|---|
| `Uploader.execute_upload`, the START reply (both the first and the uncompressed retry) | `validate_ack_response` raises `InvalidResponseError`; a compressed START falls back to uncompressed | if `parse_nack(response)` gives `(0x70, err)`, call `raise_for_upload_start_refusal` first; a typed refusal is raised at once and does not trigger the fallback |
| `Uploader.maybe_upload_partial`, START NACK on 0x76 | logs and falls back to a full upload | call `raise_for_upload_start_refusal(0x76, err)` before the fallback |
| `Uploader.negotiate_pipe` and `negotiate_pipe_partial`, START NACK | falls back to the legacy path | call `raise_for_upload_start_refusal(0x80, err_code)` before the fallback |
| `OpenDisplayDevice.write_config`, after each of the two reads | `validate_ack_response` | call `raise_for_config_write_refusal(response)` first |

Messages: `NeedsMigrationError`: "The device has no drive data for its display (firmware 3.0 needs a migrated config); write a config that includes the panel's drive packets." `PanelBusyError`: "The panel was still busy when the upload started; retry in a few seconds." `ConfigWriteBusyError`: "The device is refreshing its display and did not store the config; retry after the refresh."
