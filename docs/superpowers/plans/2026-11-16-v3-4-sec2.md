# Piece 4: Secure Session v2 (SEC2) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read `EXECUTOR_RULES.md` in this folder first.

**Goal:** Open an authenticated, encrypted session with a claimed firmware 3.0 device, claim an unclaimed one, rotate its key and unclaim it, with 2.x devices untouched.

**Architecture:** SEC2 plugs into the seam built in piece 1: `Sec2Session` implements the `Session` protocol of `device/channel.py`, next to `LegacySession`. Everything cryptographic is pure and lives in a new `sec2/` package that mirrors the website's `od-sec2.js` function by function and is tested against the shared vector file. The handshakes are small state machines over the transport. Keys live in a store the caller provides.

**Tech Stack:** Python 3.13, `cryptography` (already a dependency: AES-CMAC, AES-CCM, P-256 ECDH), `uv`, pytest, ruff, mypy strict, pylint, prek.

**Spec (normative):** `Firmware_Unified` `docs/SECURITY_V2.md` (2,965 lines; the sections to read are named per task). Reference implementation: `Web` `origin/v3/website` `httpdocs/js/od-sec2.js`, `od-sec2-session.js`, `od-sec2-policy.js`, `od-keystore.js`, and their tests. Vectors: `Web` `tests/fixtures/sec2_vectors.json` (schema `opendisplay-sec2-vectors/1`, spec revision 5).

**Depends on:** pieces 2a and 2b merged. Hardware claim testing depends on piece 3a (a device without a working panel cannot show the code).

## Read this first: what can go wrong

- **A cryptographer has not reviewed the key derivation** (the status deck lists it as open). Implement what the spec says, exactly, and do not improve it.
- **This code can lock a device.** A claim or rotation that stores a key the client then loses means a factory reset (five power cycles or the reset pin). The key store rules in Task 6 exist to prevent that. Never delete a key except after an authenticated success or an authenticated unclaim (spec § 8.8).
- **The opcodes and a few values are marked provisional in the spec.** Re-read § 3.1 and the "Open items" list in the vector file before starting.
- **Never log a key, a nonce, a shared secret or a confirmation tag.** Add `field(repr=False)` on every dataclass field that holds one, including `LegacySession.session_key` (a deferred minor from piece 1).

## Decisions to confirm with the user

1. **Key storage is the caller's.** The library defines a `KeyStore` protocol and ships two implementations: in-memory, and a JSON file for the CLI (`~/.config/opendisplay/keys.json`, mode 0600). Home Assistant implements the protocol on its config entry.
2. **A migrated 2.x key is rotated to a device-generated key by default** after the first successful SEC2 session, as the spec asks, with an opt-out (`rotate_legacy_key=False`).
3. **Typed credentials.** `LegacyKey(bytes)` for 2.x and `DeviceKey(bytes)` for 3.0; a plain `encryption_key=` keeps working and is treated as a candidate for whichever scheme the device speaks.
4. **Which device is claimed first for testing.** The E1002 is on 3.0.2 without config. Claiming it requires its panel to work (piece 3a) or the spec's no-panel path (§ 8.6). A claimed device with a lost key needs five power cycles to reset: confirm the user is at the device.

## Global Constraints

- Everything in `EXECUTOR_RULES.md`.
- 2.x behaviour and bytes do not change. `tests/unit/test_legacy_session_vectors.py` stays green.
- All SEC2 handshakes are BLE only. Over LAN they are refused by the device (`WRONG_TRANSPORT`); the library does not attempt them on a `TcpTransport`.
- Comparisons of tags, proofs and codes use `hmac.compare_digest`.
- A received public key is validated (spec § 2, "Point validation") before any ECDH call.
- Sealed frames are never split. The usable frame is `min(negotiated MTU - 3, 244)`.

## Review Focus

1. **A wrong key on SEC_AUTH** (`AUTH_FAILED`, unauthenticated). The session is not opened, the stored key is kept, and the next candidate key (up to three, § 8.8) is tried.
2. **Three sealed frames with bad tags** end the session on the device. The client must surface that as a session loss and re-authenticate, not retry the same frame forever.
3. **A plaintext frame arriving inside a session.** Only the frames § 9.5 lists are accepted in plaintext; anything else is rejected, not parsed.
4. **Counter handling on retransmission.** A PIPE retransmit must use a new counter (as `LegacySession.seal` does); counters never repeat and never go backwards; a received counter that is not strictly greater than the last is rejected.
5. **Rotation interrupted between "device stored the new key" and "client stored it".** The client must hold both keys until the new one has opened a session (stage, then promote).
6. **A device that is `LOCKED` or `CLAIM_PENDING`**, and a claim attempt outside claim mode (`NOT_IN_CLAIM_MODE`): each gives a typed error that tells the caller what the user has to do.
7. **MTU 23.** Handshake fragments must work at 20 bytes; sealed traffic cannot, and the error must say so.

### Task 1: Primitives, against the vectors

**Read:** spec § 2. **Vectors:** `V0_primitives`.

```python
def cmac(key: bytes, message: bytes) -> bytes                                  # 16 bytes
def ccm_encrypt(key: bytes, nonce13: bytes, aad: bytes, plaintext: bytes) -> bytes   # ct || 12-byte tag
def ccm_decrypt(key: bytes, nonce13: bytes, aad: bytes, ct_tag: bytes) -> bytes      # raises InvalidTag
def generate_key_pair() -> tuple[PrivateKey, bytes]                            # (private, Q = X||Y, 64 bytes)
def key_pair_from_scalar(d: bytes) -> tuple[PrivateKey, bytes]                 # tests only
def is_valid_point(q: bytes) -> bool                                           # X < p, Y < p, on the curve
def ecdh(private: PrivateKey, peer_q: bytes) -> bytes                          # 32-byte x-coordinate; validates peer_q first
```

Tests: every entry of `cmac_rfc4493`, `ccm_m12_l2`, `p256_generator`, `p256_ecdh` from the vector file; `ccm_decrypt` with one flipped tag bit raises; `is_valid_point` rejects all-zero, a point with `X >= p`, and a point off the curve; `ecdh` with an invalid peer point raises before calling the library (assert with a mock on the underlying exchange). `cmac` may reuse `opendisplay.crypto.aes_cmac`.

### Task 3: Wire layer

**Read:** spec § 3, § 5.1, § 8.1, § 9.2, § 9.4, § 11.


Tests: the fragment vectors in `V3_claim` at `frag_max` 20; a body that is an exact multiple ends with a full LAST fragment; out-of-order index, over-long body and a short LAST all raise; the real SEC_STATUS frame from hardware, `005402002135020000441bf6c96440100e0803` (E1002, 3.0.2, fresh claim mode, in `scratch/captures-OD4064C9-fw3.0.2.md`), decodes to `sec_ver` 2, `state` UNCLAIMED, CLAIM_MODE flag set, `window_s` 565, `timeout_s` 3600, `renders_left` 3. Check those numbers against § 5.1 by hand before pinning them.

Also add `OpenDisplayDevice.read_sec_status()` (plaintext, like `read_ident`) and show the state in `opendisplay info`.

### Task 4: The sealed session

**Read:** spec § 9 entirely (9.1–9.7).

```python
@dataclass
class Sec2Session:                       # implements device/channel.py Session
    k_h2d: bytes = field(repr=False); k_d2h: bytes = field(repr=False)
    send_counter: int = 0; recv_counter: int = 0
    established_at: float = 0.0
    direct_chunk_size: int = ENCRYPTED_CHUNK_SIZE        # 154 until the protocol header raises it (§ 9.4)
    def seal(self, frame: bytes) -> bytes         # [cmd_hi][cmd_lo][ctr:4 LE][C][T:12], aad = 02||cmd
    def is_sealed(self, raw: bytes) -> bool       # raw[0] == 0xE5
    def open(self, raw: bytes) -> bytes           # returns the plaintext response frame; checks the counter
    def pipe_data_size(self, frame_eff: int) -> int      # frame_eff - 18 - 1
async def authenticate(transport: Transport, k_dev: bytes, *, frag_max: int) -> Sec2Session   # HELLO / FINISH
```

`SecureChannel` changes: it must reject, inside a SEC2 session, any unsealed frame that § 9.5 does not allow (Review Focus 3). Add the rule as a method on the `Session` protocol (`allows_plaintext(raw) -> bool`; `LegacySession` returns `True` for everything it accepts today) so the channel stays scheme-agnostic. `upload.py` lines that use `ENCRYPTED_CHUNK_SIZE` directly for the START cap must read `session.direct_chunk_size` (a deferred minor from piece 1).

Tests: the auth vectors (HELLO body, both transcripts, session keys, `tag_c`); seal and open against the sealed-record vectors; first frame uses counter 1; a replayed or lower counter is rejected; an empty payload seals to 18 bytes; a full handshake against a Python reference device (port `tests/helpers/sec2-refdevice.js` far enough to answer HELLO and FINISH and to seal replies); a wrong key gives `Sec2AuthFailedError` and opens no session.

### Task 5: Claim

**Read:** spec § 7.3–7.5, § 8 entirely.

```python
class ClaimFlow:
    async def begin(self) -> None                 # BEGIN, receive Qd + commitment
    async def exchange_nonces(self) -> None       # NONCE, receive Nd + wrapped key; the device now shows the code
    def code_matches(self, typed: str) -> bool    # compares with the locally computed code
    async def confirm(self, typed: str) -> bytes  # CONFIRM; returns K_dev after tag_d verifies; session is open
    async def abort(self) -> None
async def exit_claim_mode(transport: Transport) -> None          # "use without a key"
```

Order that protects the user: the new key is **staged** in the key store before CONFIRM is sent, and **promoted** only after `tag_d` verifies (spec: "the key is saved first, as a candidate"). A typed code that does not match the locally computed one is never sent as CONFIRM. Typed errors: `NotInClaimModeError`, `AlreadyClaimedError`, `ClaimAttemptsExhaustedError`, `DeviceLockedError`, `RateLimitedError`, `Sec2BusyError`.

Tests: all six `V3_claim` vectors end to end against the reference device; wrong code; device answers `ATTEMPTS_EXHAUSTED`; the no-panel acknowledgement path of § 8.6.

### Task 6: Key store, rotation, unclaim

**Read:** spec § 8.8, § 10.5, § 11; `od-keystore.js`.

```python
class KeyStore(Protocol):
    def keys_to_try(self, name: str) -> list[bytes]                 # at most three, newest first
    def stage(self, name: str, key: bytes, kind: str) -> None       # a key the device may now hold
    def promote(self, name: str, key: bytes, *, uid: bytes | None = None) -> None   # proven by a session
    def forget(self, name: str) -> None                             # only after an authenticated unclaim
async def rotate_key(channel: SecureChannel, store: KeyStore, name: str) -> bytes
async def unclaim(channel: SecureChannel, store: KeyStore, name: str) -> None
```

Rotation: `ROTATE` (sealed) returns the new key wrapped; stage it; `ROTATE_CONFIRM`; open a new session with the new key; only then promote it and drop the old one. Tests include the interruption of Review Focus 5 at each step, and a `JsonFileKeyStore` round trip with file mode 0600.

### Task 7: Wire it into the device and the CLI

- `Device.security`: `state` (from SEC_STATUS and the advertisement), `claim()` returning a `ClaimFlow`, `rotate_key()`, `unclaim()`, `use_without_key()`.
- `opendisplay.connect(..., credential=..., key_store=...)`: on a 3.0 device read SEC_STATUS, pick SEC2 when `sec_ver` is 2 and the device is claimed, try the stored keys, open the session on the channel. On a 2.x device, today's path.
- CLI: `opendisplay claim`, `opendisplay unclaim`, `opendisplay rotate-key`, and `--key` continuing to work.
- Remove the `--drop-key` refusal in `migrate` (piece 3a) in favour of the real handover of § 10.5.

### Task 8: Hardware — every step needs the user at the device

1. Read-only: `read_sec_status()` on the E1002.
2. With a working panel (piece 3a done): put the device in claim mode (two quick power cycles), run `opendisplay claim`, the user reads the 6-digit code from the panel. Expected: claimed, key in the store, `opendisplay info` works with the session.
3. Upload an image inside the session, full and (where supported) partial.
4. `rotate-key`, then reconnect with the new key only.
5. `unclaim`. Expected: device open again, key forgotten.
6. Wrong-key and wrong-code attempts, to see the errors a user would see.
If any step leaves the device claimed with no usable key: stop, tell the user, and do the five-power-cycle factory reset together.
